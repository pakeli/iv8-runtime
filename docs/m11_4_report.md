# M11-4 Report — `queueMicrotask`

Date: `2026-10-27` · Status: **landed and verified on real V8 (Linux + Windows)**

Boundary document: `docs/m11_4_queue_microtask.md` (authoritative for behavior and
non-goals). This page is the delivery record: what was asked, what shipped, how it
was verified, and what remains open.

## 1. Goal

Add the fourth compatibility slice under the M11 line: the standard
`queueMicrotask(callback)` global, feeding the existing V8 microtask queue that
`Page.run_jobs()` already drains — no new Python API, no fifth pump, no automatic
event loop.

Explicit constraints: a non-callable argument throws a JS `TypeError` before
anything is enqueued; callbacks run FIFO and interleave with `Promise` reactions;
`load()` discards the old generation's pending microtasks; `run_jobs()` after
`dispose()` raises `JSContextDisposedError`; the microtask queue remains
independent of the timers, animation frames, and idle callbacks.

## 2. What was implemented

**JS surface** (per generation, installed by `install_page`):

- `queueMicrotask(callback)` — enqueues on the current context's V8 microtask
  queue and returns `undefined`.
- No `cancelMicrotask`; microtasks are not cancellable in the standard API.
- `window.queueMicrotask === queueMicrotask` because `window` is the intrinsic
  global object.

**Python surface**: no new method. `Page.run_jobs()` is still the only trigger;
the runtime still has exactly four manual pumps.

**Semantics**:

- callbacks run FIFO, at most once per registration;
- `queueMicrotask` interleaves with `Promise.then` reactions in enqueue order;
- a microtask queued from inside a microtask appends to the same checkpoint;
- an exception thrown by a microtask is swallowed by V8's explicit checkpoint,
  matching the existing manual-pump error policy;
- `load()` tears down the generation and discards pending microtasks;
- `run_jobs()` after `dispose()` raises `JSContextDisposedError`;
- the microtask queue is independent of the timer, animation-frame, and idle
  queues; no pump drains another's work.

## 4. Cold-build fixes required for verification

The fork had no warm V8 monolith cache, which exposed two pre-existing cold-path
issues unrelated to M11-4 runtime code:

1. **Linux/manylinux (`a1869e9`, `0305b49`)** — `tools/build_v8_manylinux.sh`
   cloned the current depot_tools and immediately ran `fetch`, while
   `DEPOT_TOOLS_UPDATE=0` suppressed the wrapper's automatic bootstrap. The first
   fix added an `ensure_bootstrap` call; the second corrected the guard to look for
   `python3_bin_reldir.txt` (generated by bootstrap) rather than the checked-in
   `python-bin/python3` wrapper, so the bootstrap actually runs. The script now
   also fails fast if the marker is still missing.
2. **Windows (transient)** — the first cold build failed while cloning V8's
   `third_party/clang-format/script` DEPS entry (`update_ref failed ... nonexistent
   object`), a truncated git pack on the runner. A rerun succeeded; the V8 cache
   was then reused. No Windows script change was needed.

Both fixes are build-only; `db2dd93..0305b49` touches only
`tools/build_v8_manylinux.sh`, so the runtime code tested is the M11-4 commit
itself.

## 6. Non-goals (confirmed absent)

- a new Python API or a fifth pump;
- an automatic event loop, background thread, or automatic microtask checkpoint;
- a real clock, `performance.now()`, or task deadlines;
- `MutationObserver` (landed separately in M11-5 — see
  `docs/m11_5_mutation_observer.md`);
- `scheduler.postTask` / `scheduler.yield` / task priorities;
- `queueMicrotask` cancellation (not part of the standard API);
- `requestPostAnimationFrame`, rendering, layout, networking, navigation,
  storage, canvas, or WebGL.

`JSContext`, the first-layer DOM/script/lifecycle/form/M8 surfaces, and the
M9–M10 monitoring channels are unchanged. `test_queue_microtask.py` includes
explicit guards that `scheduler`, `performance`, and other non-goal surfaces
remain absent.

## 8. Open questions

1. **Four pumps, no composed driver.** The runtime still exposes
   `run_timers()`, `run_jobs()`, `run_animation_frame()`, and
   `run_idle_callbacks()`, each draining one queue. `queueMicrotask` deliberately
   feeds `run_jobs()` instead of adding a fifth. Whether to add an ordered driver
   remains a design decision (`docs/decision_log.md` §A).
2. **No ranked compatibility matrix.** M11-1 through M11-4 were chosen by
   direction rather than from a source-backed survey. Building the ranked backlog
   is `docs/next_tasks.md` Priority 4 and should precede `M11-5`.
3. **M11-5 is not chosen.** After this verification, the next execution handoff
   is the ranked matrix and an explicit M11-5 slice.

## 9. Recommended next step

Do **Priority 4** now: build the ranked compatibility backlog and choose
`M11-5` from evidence rather than intuition. The four-pump composition question
is a separate, deliberately deferred design decision.
